# JX3 Raid Manager（剑网三副本管家）

> 一款为《剑网3》团长与多号玩家打造的本地化团队管理工具，集中解决副本收入记录、账号角色管理、掉落统计、BOSS CD 追踪等日常痛点。

![JX3 Raid Manager 预览图](https://cdn.jx3box.com/upload/post/2026/2/24/29953_1557557.png)

## ✨ 核心功能

- **💰 智能工资结算** - 记录团队副本、百战、试炼之地等玩法的收入与支出，支持备注、明细查看与汇总统计
- **📊 数据概览更清晰** - 首页支持按时间范围查看收益、记录数、稀有掉落等关键数据
- **👥 账号与角色统一管理** - 支持手动添加或扫描游戏目录自动识别本地账号，支持本人/代清分类管理
- **↕️ 账号拖动排序** - 账号管理页支持直接拖动账号栏调整显示顺序，排序结果自动保存
- **🔍 角色搜索与筛选** - 团队副本、百战、试炼之地都支持按角色名、区服、账号快速搜索
- **🗡️ BOSS CD 追踪** - 25 人团队副本 BOSS 击杀状态记录与 CD 展示
- **🎁 稀有掉落统计** - 玄晶、马具、宠物、挂件、坐骑、外观、称号、秘籍等特殊掉落统计，支持按掉落类型多选筛选
- **⚔️ 百战/试炼之地支持** - 除团队副本外，也支持百战与试炼之地的数据管理
- **🌙 本地化存储** - 所有数据默认保存在本地设备，安装版支持应用内自动更新

## 🚀 快速上手

### 1. 下载客户端

前往 [GitHub Releases](https://github.com/lesswhite810/jx3-raid-manager/releases) 下载最新版：

- **安装版** - 支持应用内自动更新，适合长期使用
- **便携版** - 免安装，适合随身携带或手动备份

### 2. 配置游戏目录

启动应用后，在配置页填写《剑网3》游戏目录（例如 `E:\Game\SeasunGame`），程序会自动补全到正确的游戏数据目录。

### 3. 添加或扫描账号

进入"账号管理"页面后，你可以：

- 点击"**角色分析**"自动扫描游戏目录，导入本地账号与角色
- 点击"**新增账号**"手动添加账号，再在账号下添加角色

### 4. 开始记录副本数据

进入对应玩法页面后，点击"添加记录"，选择角色、副本、难度，输入工资收入即可。

### v2.1.52（2026-08-09）

- **自动扫描历史遗留记录复核** - 此前若应用被异常关闭、JX3 崩溃或电脑重启，上次会话未收尾的副本记录会一直卡在"进行中"状态无法确认；同时部分因聊天日志未及时落盘而未识别到掉落和工资的"待确认"记录也无法自动补充。现在每次自动扫描轮询开始时会先复核这两类历史记录：对"进行中"记录重新判定是否已结束（含副本切换、6 小时兜底等信号），对"无掉落无工资的待确认"记录重新扫描补充数据。若新扫描仍未识别到掉落和工资但原记录已有数据，会保留原数据避免丢失。
- **修复无底薪副本无工资记录时收入虚高** - 此前团队未宣布底薪时，若对应副本的全部聊天记录中不包含"你获得：XXX金"的工资消息，自动扫描会把角色在此期间的全部收入累加成副本收入，显示金额远高于实际工资。现在不再回退累加收入总和，找不到工资记录时收入记为 0，等后续扫描识别到真实工资后再补充，避免虚高
- **修复无底薪副本工资已发但仍卡"进行中"** - 未宣布底薪的副本中，团长发放工资（拍卖）后若 JX3 未退出、角色仍在线且副本未全部击杀，记录会一直保持"进行中"无法确认，最长要等 6 小时兜底。现在检测到副本已出现工资收入和掉落分配后，立即判定副本结算完成，转为"待确认"供手动确认

### v2.1.51（2026-08-04）

- **修复无底薪时副本收入虚高** - 此前在团队未宣布"每人底薪"的情况下，自动扫描会把副本结束后团长发放的工资以及后续所有拍卖分成都累加成总收入，导致显示金额远高于实际工资（例如 300 金工资被算成 1306 金）。现在改为取最后一个战斗日志之后的第一条收入记录作为副本收入，更符合"工资只发一次"的实际情况
- **修复进入下一个副本后上一副本仍显示"进行中"** - 此前在同一账号连续打多个副本时，第一个副本若未全清 BOSS、JX3 仍未退出、角色仍在线，会一直保持"进行中"状态无法转为"待确认"。现在只要检测到角色已经开始打后续副本，上一个副本就会被判定为已结束并可确认
- **修复安装或迁移时数据库被误删** - 此前在首次安装或切换数据目录时，若目标目录已存在空数据库文件，可能被误判为"权威文件"并删除源数据库，导致已有记录丢失。现在改为仅在源文件与目标文件完全一致时才清理源文件，否则保留源文件作为备份，避免误删
- **修复柳公子团灭被误判为击杀** - 此前柳公子等多阶段 BOSS 团灭时，可能因为分身离场时间跨度达到 120 秒被错误判定为击杀。现改为依赖"BOSS 死亡迹象 + 之后无重生"组合判定，团灭时 BOSS 会重生（face_dir 从 192 回到 0），能被正确识别为拉托。同时也修复了部分无宝箱的击杀漏判

### v2.1.50（2026-08-03）

- **切换数据目录时增加冲突提示** - 切换自定义数据目录或恢复默认目录时，如果目标目录已存在数据库文件，会弹窗提示用户选择处理方式：覆盖目标文件或取消切换，避免误操作覆盖重要数据
- **修复安装版与便携版数据互相串走** - 此前同时安装了安装版和便携版时，后打开的版本会把先打开版本的数据库文件迁移到自己的目录，导致两边数据互相覆盖或丢失。现在安装版和便携版的配置文件完全独立，两个版本可以稳定共存，互不干扰。
- **修复切换数据目录时覆盖标记被提前消费** - 此前用户确认覆盖目标目录已有数据库文件后，应用运行期间的其他内部调用会意外触发数据迁移，导致覆盖标记被清除、迁移在重启前提前执行。现在数据迁移仅在应用重启时执行一次，确保用户选择（覆盖或保留）在重启时正确生效。
- **修复刷新装分后角色排序错乱** - 此前启动应用自动刷新装分或手动刷新装分后，已导入角色的显示顺序会因装分变化被重新打乱（例如原本在前的角色被挤到后面）。现在刷新装分后角色顺序保持稳定，新增角色追加到末尾。
