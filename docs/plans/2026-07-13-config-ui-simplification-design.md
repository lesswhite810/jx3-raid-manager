# 系统配置界面精简设计

日期：2026-07-13
状态：已确认，待实现

## 背景与问题

当前 `ConfigManager.tsx`（471 行）将 4 个功能模块以等权重卡片纵向堆叠：

1. 版本与更新（卡片 + InfoCard 三宫格 + 检查更新按钮）
2. 游戏配置（卡片 + 赛季 + 目录输入 + 扫描 + 客户端列表）
3. 数据存储（卡片 + 位置标签 + 路径 + 切换/还原按钮）
4. 重新初始化（卡片 + 危险操作 + 二次确认面板）

核心问题：整体缺少主次区分，导致视觉层次不清、信息过多、页面过长。4 个卡片等权重排列，重要配置（游戏目录）和不常用功能（重新初始化）抢占同样注意力。

## 设计方案

将 4 个等权重卡片精简为 **3 层视觉结构**：

| 层级 | 功能 | 视觉形态 | 理由 |
|------|------|----------|------|
| 层级 1·主 | 游戏配置 | 完整卡片 | 核心配置，进来第一眼就该看到 |
| 层级 2·次 | 数据存储 | 紧凑卡片 | 次要配置，保留卡片但精简辅助元素 |
| 层级 3·页脚 | 版本与更新 | 一行状态栏 | 不是配置项，是状态展示 |
| 融入层级 1 | 重新初始化 | 游戏配置卡片底部文字链接 → 弹窗 | 本质是配置项的重置操作，非独立功能 |

### 整体页面结构

```
配置页面
├── 标题区（精简，仅 "系统配置"，去掉副标题）
├── [层级1·主] 游戏配置卡片
│   ├── 当前赛季 + 游戏目录输入 + 扫描按钮
│   ├── 路径校验提示（保留校验结果，去掉补全说明文字）
│   ├── 客户端扫描结果（条件渲染，逻辑不变）
│   └── 底部分隔线 + "重置配置"文字链接（muted色，右对齐）
├── [层级2·次] 数据存储卡片
│   ├── 位置标签 + 目录路径 + 操作按钮（合并为一行）
│   └── 去掉重启提示文字（Toast 已覆盖）
└── [层级3·页脚] 版本状态栏
    ├── 左：版本号 · 运行形态 · 更新状态
    └── 右：检查更新 / 查看详情 文字链接
```

## 详细设计

### 1. 游戏配置卡片（层级 1·主）

保持现有交互逻辑，精简辅助元素并融入重置功能。

变化点：
- **卡片头部**：去掉副标题"设置游戏安装路径以实现自动扫描等功能"，图标 + 标题足够表意
- **路径校验提示**：去掉"支持填写安装根目录，运行时会自动补全到 Game\JX3\bin\zhcn_hd"说明文字，补全逻辑在 input placeholder 中轻量提示
- **重置配置入口**：卡片底部加 `border-t border-base` 分隔线，下方放 muted 色"重置配置"文字链接，不带图标，右对齐
- **重置确认弹窗**：点击后弹出居中弹窗（复用项目 `fixed inset-0 bg-slate-900/60 backdrop-blur-sm` 模式），内容："应用将立即重载，未保存的数据可能丢失。副本记录、AI 配置等数据不会删除。"，确认按钮 `bg-red-600`，取消按钮 `btn btn-secondary`

布局示意：
```
┌─────────────────────────────────────────────┐
│  [FolderOpen]  游戏配置                       │
│                                                │
│  当前赛季    当前赛季名称                      │
│                                                │
│  游戏目录    [______输入框______] [扫描]       │
│              ✓ 路径有效                        │
│                                                │
│  [条件] 客户端扫描结果网格                     │
│                                                │
│  ────────────────────────────────────         │
│                               重置配置        │
└─────────────────────────────────────────────┘
```

### 2. 数据存储卡片（层级 2·次）

保留核心功能，压缩为一个紧凑卡片。

变化点：
- **卡片头部**：去掉副标题"配置数据库与日志文件的存储位置"
- **布局压缩**：位置标签 + 路径 + 操作按钮合并为一行。位置标签作为 inline badge 紧贴路径左侧，按钮跟在路径右侧
- **去掉重启提示**：去掉底部"修改目录后需要重启应用才能生效"说明文字，Toast 已有此提示

保留项：
- 路径等宽字体 `font-mono select-all`
- 位置标签动态配色（custom→emerald、install→blue、其他→slate）
- 安装版标签

布局示意：
```
┌─────────────────────────────────────────────┐
│  [Database]  数据存储                         │
│                                                │
│  [自定义目录] D:\AppData\JX3 [切换目录] [还原] │
└─────────────────────────────────────────────┘
```

### 3. 版本状态栏（层级 3·页脚）

用一行文字替代原来的整个版本与更新卡片。

设计细节：
- **样式**：`border-t border-base` 分隔线 + `py-3`，文字 `text-xs text-muted`
- **左侧信息**：版本号 · 运行形态 · 更新状态，三项用 `·` 分隔
- **右侧操作**：默认显示"检查更新"文字链接（`text-muted hover:text-primary`），检查中显示"检查中..."并禁用
- **发现新版本时**：左侧更新状态变为 emerald 色"发现新版本 v2.1.44"，右侧变为"查看详情"链接
- **去掉 InfoCard 子组件**：三宫格不再需要
- **去掉新版本提示条**：状态栏左侧高亮已足够传达

交互逻辑不变，仍调用 `onCheckForUpdates`。便携版状态文案保持现有逻辑。

布局示意：
```
─────────────────────────────────────────────
v2.1.43 · 安装版 · 已是最新版本        检查更新
```

### 4. 重置确认弹窗

复用项目现有弹窗模式（`fixed inset-0 bg-slate-900/60 backdrop-blur-sm` 遮罩 + 居中卡片）。

内容：
- 标题："确认重新初始化"
- 正文："应用将立即重载，未保存的数据可能丢失。副本记录、AI 配置等数据不会删除。"
- 确认按钮：`bg-red-600 text-white`，文案"确认重置"
- 取消按钮：`btn btn-secondary`，文案"取消"
- 确认后调用 `resetAll()` → `window.location.reload()`

## 代码清理

1. **删除 InfoCard 子组件**：接口定义和组件实现全部移除
2. **移除所有卡片副标题**：4 个卡片的 `<p className="text-xs text-muted">` 副标题元素删除
3. **移除标题区副标题**："配置项修改后会自动保存，无需手动点击保存"删除
4. **Props 不变**：ConfigManager 的 props 完全不变，不影响 App.tsx 调用方
5. **预估行数**：从 471 行降至约 300 行

## 不涉及的范围

- **后端无改动**：所有 Tauri invoke 调用保持不变
- **App.tsx 无改动**：props 传递和渲染逻辑不变
- **交互逻辑不变**：扫描、路径校验、目录切换、更新检查的核心逻辑完全保留
