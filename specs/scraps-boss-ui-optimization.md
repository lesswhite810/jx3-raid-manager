# 散件老板界面分析与优化方案

> 范围：副本管理中两个含"散件老板"区块的弹窗
> - `AddRecordModal.tsx`（添加/编辑副本记录，手动入口）
> - `PendingRecordsPanel.tsx`（自动扫描待确认记录，编辑弹窗）
>
> 约束：遵循 `specs/design-tokens.md`（扁平极简、emerald 收入/激活、amber 支出、red 仅删除/错误、散件估价用中性灰 `text-muted`）

---

## 1. 现状结构对比

| 维度 | AddRecordModal（手动新增） | PendingRecordsPanel（扫描确认） |
|------|---------------------------|-------------------------------|
| 身份开关 | 卡片式复选，与 7 种材料并排进同一网格 | 朴素 `checkbox + label` |
| 物品来源 | 前端硬编码 7 种材料白名单卡片，勾选加入清单 | 后端扫描结果，只读展示 |
| 清单可编辑性 | 数量 / 单价 / 删除均可编辑 | 仅单价可编辑（npc 只读） |
| 单价框宽度 | `w-20` | `w-24` |
| 类型·来源标签 | 无 | 有（`材料·手填` 等） |
| 估价合计 | 右对齐金额 | 左提示 + 右金额 + "未填按 0 计入"说明 |
| 装备类支持 | 无（白名单仅材料） | 有（后端识别 0 金装备） |

## 2. 问题清单

### P1 两个入口视觉割裂
同一功能在两个弹窗采用完全不同的视觉语言：A 用卡片式网格，B 用朴素 checkbox。用户在两个入口间切换时体验不一致，认知成本高。

### P2 身份开关与物品选择语义层级混淆（AddRecordModal）
"散件老板"是**统计开关**（是否把估价计入收支），7 种材料是**物品添加**操作。两者并排进同一卡片网格，语义不同却视觉同构，用户难以区分"勾散件老板"和"勾某个材料"的区别。

### P3 材料白名单常驻造成视觉噪音（AddRecordModal）
7 种材料卡片 + 1 个开关卡片共 8 个卡片常驻显示，即便用户不是散件老板也占据约 1/3 弹窗高度。对非散件老板用户（多数场景）是无意义噪音，挤压核心收支/掉落区。

### P4 清单项布局拥挤，窄屏易错乱
`PendingRecordsPanel` 清单项把 `名称×数量` + `类型·来源` 标签 + `单价框(w-24)` 挤进单行，窄屏或长物品名时换行错乱。`AddRecordModal` 清单项把 `数量框` + `单价框` + `删除` 挤一行，操作区局促。

### P5 估价合计样式不统一
两处合计的文案、对齐、提示不一致；`AddRecordModal` 缺少"未填单价按 0 计入"的说明，用户不知空单价如何处理。

### P6 手动新增缺少散件装备入口（AddRecordModal）
白名单只有 7 种材料，无法手动记录"0 金散件装备"。设计文档（`scraps-boss-design.md` §3.3）中散件包含 `category=='equipment' && total_price==0` 的装备，手动入口却无法覆盖。

## 3. 优化方案

### 3.1 统一设计目标

1. **两弹窗共用同一散件区块结构**：身份开关 + 清单编辑器，视觉语言一致。
2. **分离两个语义层级**：身份开关独立成区，物品管理单独成区。
3. **降低非散件老板噪音**：未勾选且无散件物品时，区块收起为单行开关；勾选或有物品时展开清单。
4. **抽出共享组件**：新建 `ScrapsItemsEditor` 子组件，两弹窗复用，消除重复实现。
5. **对齐 design-tokens**：散件估价用 `text-muted`/`text-slate-500`，散件老板激活用 `emerald`，容器单色背景 + 轻边框，无重阴影。

### 3.2 结构重构

#### 身份开关独立化
- "散件老板"从卡片网格抽出，作为区块标题行的开关：
  ```
  ┌─ ☐ 散件老板 ─────────── （勾选后散件估价计入收支统计）─┐
  │  ...清单区...                                          │
  └────────────────────────────────────────────────────────┘
  ```
- 复选框激活色 `emerald`，配 `Boxes` 图标。
- 与上方"特殊掉落"区用相同 section header 样式（`w-1 h-4 bg-primary` 竖条 + 标题），但开关内联在标题右侧，形成区分。

#### 物品管理重构（AddRecordModal）
- 取消 7 种材料常驻卡片网格。
- 改为"添加散件物品"入口：
  - 方案 A（推荐）：一个 `+ 添加散件` 按钮，点击展开材料白名单快捷标签 + 自定义输入。
  - 方案 B：材料白名单作为可折叠的快捷标签组，默认收起。
- **新增自定义散件**：支持手动输入物品名 + 数量 + 单价 + 类型（材料/装备），覆盖装备场景（补 P6）。
- 清单为空时显示占位文案"暂无散件物品，点击添加"。

#### 清单编辑器统一（ScrapsItemsEditor）
两弹窗共用清单渲染，差异通过 props 控制：

| Prop | AddRecordModal | PendingRecordsPanel |
|------|----------------|---------------------|
| `editable`（数量/删除） | `true` | `false` |
| `unitPriceEditable` | `true`（全部） | `npc` 只读，其余可编辑 |
| `showSourceLabel` | `false` | `true` |
| `allowAddCustom` | `true` | `false`（扫描结果不可加） |

清单项新布局（两行，解决 P4）：
```
┌──────────────────────────────────────┐
│ 维峰丹 ×2            材料·手填       │  ← 第一行：名称+数量 + 来源标签
│ 单价 [____]金              [删除]    │  ← 第二行：单价输入 + 删除
└──────────────────────────────────────┘
```
- 名称 `truncate` + `title` 全名；数量内联在名称后。
- 来源标签靠右，`text-[11px] text-muted`，窄屏不与单价框抢空间。
- 单价框放宽至 `w-28`，`npc` 只读用 `bg-base` + `cursor-not-allowed`，`manual` 空值用 `amber` 边框提示手填，`jx3box` 用 `emerald` 边框。

#### 估价合计统一
两弹窗统一为：
```
┌──────────────────────────────────────┐
│ 散件估价合计（未填单价按 0 计入）  XXX金 │
└──────────────────────────────────────┘
```
- 左侧 `text-xs text-muted` 文案 + 提示；右侧 `font-mono font-semibold text-muted` 金额。
- 金额用中性灰 `text-muted`，**不**用 emerald/amber，避免与收入/支出色彩冲突（对齐 design-tokens §7.3）。
- `isScrapsBoss=false` 时合计右侧追加小标签 `仅展示`（`text-[10px] text-muted`），与 RaidDetail 的 title 语义一致。

### 3.3 视觉规范对齐

| 元素 | 样式 |
|------|------|
| 散件区块容器 | `bg-base/40 rounded-lg border border-base`，无阴影 |
| 身份开关激活 | checkbox `text-emerald-600`，标签 `text-main` |
| 清单项 | `bg-surface rounded border border-base` |
| 单价框(npc只读) | `bg-base text-muted border-base cursor-not-allowed` |
| 单价框(手填空) | `border-amber-300 placeholder:text-amber-500 focus:ring-amber-400` |
| 单价框(已填/jx3box) | `border-emerald-300 focus:ring-emerald-400` |
| 估价合计金额 | `text-muted`（中性灰） |
| 删除按钮 | `text-muted hover:text-red-500`（red 仅删除） |

### 3.4 交互细节

- 身份开关默认不勾；勾选时不强制要求清单非空（允许散件老板暂无散件）。
- `PendingRecordsPanel`：扫描清单为空时显示"本次扫描未识别散件物品"，仍保留开关。
- `AddRecordModal`：添加自定义散件时，类型默认 `material`、`priceSource='manual'`、`unitPrice=null`。
- 估价合计随单价输入实时更新（两处已有 `computeScrapsValue`，保持）。

## 5. 实施清单

### 5.1 新增共享组件

- `components/ScrapsItemsEditor.tsx`
  - props：`items`、`onChange`、`editable`、`unitPriceEditable`、`showSourceLabel`、`allowAddCustom`
  - 内含：清单渲染（两行布局）、单价编辑、数量编辑、删除、添加散件入口（材料快捷标签 + 自定义输入）、估价合计
  - 复用 `computeScrapsValue`（建议抽到 `utils/scrapsUtils.ts`，两弹窗共享）

### 5.2 AddRecordModal 改动

- 删除现有散件老板卡片网格（约 L464–L596）。
- 替换为：身份开关 section header + `<ScrapsItemsEditor editable unitPriceEditable allowAddCustom />`。
- 移除组件内 `SCRAPS_MATERIAL_WHITELIST` 常量（迁入 `ScrapsItemsEditor` 或 `data/`）。
- 提交逻辑保持（`isScrapsBoss` / `scrapsItems` / `scrapsValue` 已就绪，无需改）。

### 5.3 PendingRecordsPanel 改动

- 替换现有散件老板朴素区块（约 L736–L828）为：身份开关 section header + `<ScrapsItemsEditor editable={false} unitPriceEditable showSourceLabel />`。
- `editForm.scrapsItems` 编辑逻辑迁入 `ScrapsItemsEditor` 的 `onChange` 回调。
- `handleSubmitEdit` 中 `computeScrapsValue` 调用保持。

### 5.4 验证点

- 两个弹窗散件区块视觉一致（开关样式、清单布局、合计文案）。
- 非散件老板用户：开关未勾且无散件时，区块仅占单行开关高度，不再常驻 8 卡片。
- `AddRecordModal` 可手动添加自定义散件装备。
- `PendingRecordsPanel` 的 `npc` 单价只读、`manual` 空值 amber 提示、`jx3box` emerald。
- 估价合计金额为中性灰，不与收入/支出色冲突。
- 旧记录（无 `scrapsItems`）正常显示，无报错。
- 暗色模式下各状态颜色正确。
